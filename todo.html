nuxtMinesweeper 接下来该做什么

这个项目已经有清晰的核心玩法：Nuxt 4、Canvas 无限棋盘、WebSocket 多人同步、账号系统、排行榜和本地持久化。下一步最值得投入的不是继续堆功能，而是先把稳定性、安全边界和可验证性补起来。

当前判断

玩法原型完成度高，工程成熟度还偏早期。建议用 3 个阶段推进：先修可靠性，再完善多人体验，最后扩展长期内容。

8 推荐优先任务
P0 先处理服务端和安全
0 发现测试文件
1 核心页面入口

项目现状

已实现的主线包括 Canvas 棋盘渲染、拖拽缩放、登录注册、WebSocket 操作广播、实时排行榜、玩家光标和音效。代码规模不大，适合先做几处高杠杆修补。

Nuxt 4 Vue 3 Canvas 2D Nitro WebSocket NuxtHub KV scrypt

主要观察

  • README.md 里部分描述超前于实现，例如 AES-256-GCM 加密存储、完整移动端体验、企业级安全。
  • server/utils/gameLogic.ts 的零区域展开会在循环中调用异步加分，但当前没有 await，可能导致分数和排行榜更新顺序不稳定。
  • server/utils/jwt.ts 直接用字符串比较签名，建议改成常量时间比较，并强制生产环境配置 JWT_SECRET。
  • 目前没有测试、CI、lint/typecheck 脚本，后续改多人同步逻辑时缺少安全网。
  • 数据层仍是 KV/文件式世界快照，短期够用，但需要控制无限地图状态增长。

推荐节奏

第一轮用 1-2 天补 P0，让项目不容易在多人操作下出错；第二轮用 3-5 天补测试、错误体验和 README 对齐；第三轮再做聊天室、成就、热力图这些能让游戏更有生命力的功能。

修复零区域展开的异步计分

把 expendZero 改为可 await 的流程，避免大面积展开时分数、排行榜和持久化状态出现竞态。

P0
验收：连续点击大片空白区后，玩家分数与实际翻开安全格数量一致；排行榜广播结果稳定。

加固登录与 JWT 安全边界

生产环境必须配置 JWT_SECRET，签名比较使用 timingSafeEqual，注册接口增加用户名、密码、颜色白名单校验。

P0
验收：无密钥的生产启动会明确失败；非法颜色、过短密码、异常用户名无法注册；过期 token 被稳定拒绝。

补最小测试和 CI

先覆盖地雷生成、相邻雷数、点击/插旗/自动展开、用户注册登录、JWT 过期校验。再加 GitHub Actions 跑 typecheck、build、unit tests。

P0
验收：新增 test、typecheck 脚本；PR 或推送时自动跑完；核心游戏逻辑至少有单元测试。

整理 README，让文档等于现实

保留项目愿景，但把“已实现”和“规划中”分开，尤其是安全、持久化、移动端、聊天室、成就等描述。

P1
验收：新用户只按 README 操作可以启动项目；功能列表不会把未实现能力写成已完成。

改善 WebSocket 断线和错误体验

当前会自动重连，但用户操作失败主要靠 alert。建议增加非阻塞 toast、重连退避、离线状态提示和操作排队/禁用策略。

P1
验收：断网、token 失效、服务端重启时，界面能清楚显示状态，且不会弹出一串阻塞 alert。

控制无限地图状态增长

为 blocks 增加分区、压缩或清理策略，并记录世界快照大小。否则长时间多人游玩后，初始化包和持久化成本会越来越高。

P1
验收：世界数据增长可观测；初始化只发必要区域或压缩后的状态；旧区域策略有明确文档。

补齐设置面板：音量、主题、操作偏好

音效系统已存在，但缺少完整可见控制。建议把静音、音量、深浅色、移动端长按时长放进一个轻量设置面板并持久化。

P2
验收：用户刷新后偏好仍保留；移动端和桌面端都能快速找到设置。

再做多人内容：聊天、成就、热力图

稳定性补完后，再加侧边聊天、坐标快捷发送、成就勋章和探索热力图。这些会显著增强“大家在同一张无限地图上玩”的感觉。

P3
验收：聊天消息不会污染游戏操作通道；成就可持久化；热力图不会拖慢首屏加载。
